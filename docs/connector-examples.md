# Connector questions against vendor pages: a worked example

This example puts checklist rows VA-39 to VA-43 in [reference/ai-vendor-assurance.md](../reference/ai-vendor-assurance.md#connectors-agents-and-recordings) to one product of each connector kind, using only what each vendor's own public page said when read on 12 November 2026. It shows which questions a page answers and which it leaves open. It is not an assessment of any product and favours none. A page answers a row only as the vendor's claim: each row still asks for its own evidence, such as a tool list from a test tenancy or a call log, and a later page or product change can alter any cell. The checklist names no vendor, so this dated example sits outside the verified bundle.

| Row | Read-only MCP server: Dext AI Connector | Plugin in a host's catalogue: Xero plugin for Copilot Cowork | Writes held in an approval queue: Invio Xero MCP |
|---|---|---|---|
| VA-39 Tools and writes | Read-only, with 'no elevated access and no ability to make changes'; the FAQ adds that it 'can't create approvals or updates in Dext'. Open: the tool list and sign-in scopes, which the page does not give. | Described only as checking profit and loss, cash position and top customers from Microsoft 365 Copilot. Of partner plugins generally, the page says they let the agent 'read and act on data'. Open: whether this plugin has a write tool, and its tools and scopes. | Reads need no approval. Creating or changing an invoice, bill, contact, credit note, quote or manual journal makes a draft; recording payments and payroll changes are separate permissions, off by default, and a posted pay run 'cannot be reversed through Xero's API'. The Australian page counts 39 tools and the GitHub README 38. Open: the tool list and Xero scopes; the 2 counts are why the row asks for the list from a test tenancy. |
| VA-40 Read-only and switch-off | Read-only by design, per the page. Open: an administrator switch-off for every user, and how fast it reaches open sessions. | Partner plugins 'require your IT admin to make them available', and administrators control plugin availability in the Microsoft 365 admin center. Open: limiting the plugin to reads, and how fast removal reaches open sessions. | Each permission can be turned off, and payments and payroll start off. Revoking a connector or disconnecting Xero in Settings means 'access ends on the next call'. Open: a read-only option for invoices, credit notes and quotes, whose permission the page lists as reading and drafting together. |
| VA-41 Own sign-in and attribution | Authenticates through the partner's Dext account and 'only surfaces data that the user already has permission to see'. Open: the access test the row asks for. Attribution does not arise whilst nothing can be written. | Partner plugins use 'your existing sign-in', and Cowork asks for sign-in and authorisation on first use. Open: the access test, and attribution of any change in Xero. | Xero is connected per organisation on the Invio account; the assistant reaches it through a connector URL shown once. Each approval or rejection is recorded against the person in Invio's History, and roles and organisation limits are 'enforced on our servers'. Open: whether each user has their own connector URL, and whom Xero records as making a change. |
| VA-42 Exact payload and self-confirmation | Does not arise whilst nothing can be written (VA-39). | Not stated. Open. | A draft shows 'the organisation and the exact payload' (GitHub README). Payments and payroll changes need a person signed in to Invio, but other drafts can be approved 'by clearly telling your assistant to approve it, right there in the chat': a confirmation the model relays, which VA-42 does not accept. Open: a field-by-field comparison of the confirmed and sent payloads. |
| VA-43 Call records and retention | Only the data a question needs is retrieved, and the AI provider's 'own data policies also apply'. Open: any call log, who can read it and how long it and chat history are kept. | Not stated. Open. | Invio keeps 'A record of which tool ran, when, and against which organisation', and a waiting draft until it is decided or for up to 24 hours, with its financial detail cleared within 90 days. The assistant provider's handling is 'governed by your agreement with them'. Open: whether the record holds arguments and results, who can read it, how long it is kept, and chat history. |

Sources, each read on 12 November 2026: Dext, [Dext launches AI Connector](https://dext.com/en/news/dext-launches-ai-connector-letting-accounting-and-bookkeeping-practices-ask-claude-chat-gpt-and-copilot-about-their-own-practice-data) (announced 22 October 2026), with its FAQ answers; Microsoft Learn, [Available plugins for Copilot Cowork](https://learn.microsoft.com/copilot/cowork/cowork-available-plugins) (last updated 2 November 2026); Invio, [Xero MCP](https://www.invio.com.au/xero-mcp), with its FAQ answers, and the [invio-xero-mcp README](https://github.com/InvioNZAU/invio-xero-mcp).
